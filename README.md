# MANA 2.67.0

Локальный агент для Windows, который решает задачи пользователя: отвечает на
вопросы, открывает и заполняет программы на этой машине (1С, Word/Excel,
Notepad++), ищет в сети, помнит разговоры и факты. Работает как окно, как
команда в терминале и как библиотека.

Самоулучшение — подчинённый механизм: агент должен расширять собственные
возможности, когда упирается в то, чего не умеет. Архитектура переводится к
этому по плану из пяти фаз — см. «План миграции к агенту».

Хронология того, как строилась каждая часть и почему решения приняты именно
так, — в [docs/HISTORY.md](docs/HISTORY.md). Прежний README сохранён там
целиком.

## Быстрый старт

```bash
pip install -r requirements.txt

mana.cmd --interactive                 # диалог в терминале (Windows)
python mana_run.py --ask "Сколько будет 17 * 23?"
python mana_run.py --list-brains       # какие мозги готовы и чего не хватает
python mana_run.py --paths-status      # где лежит состояние и песочница
python mana_run.py --version           # продукт + версии всех подсистем
```

`mana.cmd` сам переходит в каталог проекта и берёт интерпретатор из `.venv`,
поэтому его можно запускать из любого места, в том числе из PowerShell.

Приложение с окном:

```bash
python serve_ui.py                     # интерфейс в браузере, без сборки
python build_exe.py --windowed         # собрать MANA.exe
dist/MANA/MANA.exe --self-check        # проверить, что упаковка ничего не потеряла
python scripts/build_installer.py      # установщик (нужен Inno Setup 6)
```

Установщик ставит MANA в `%LOCALAPPDATA%\Programs\MANA` без прав
администратора: приложение переписывает собственный код, а в Program Files у
него нет права на запись. Память агента (`%LOCALAPPDATA%\MANA`) при удалении
сохраняется. Сборка останавливается, если пакета из `packaging_deps.BUNDLED`
нет в окружении, — иначе PyInstaller молча собирает приложение без него.

**Windows 10.** Окно рисуется WebView2 Runtime: в Windows 11 он встроен, в 10 —
нет. MANA проверяет это до запуска окна и говорит, что поставить; без
WebView2 работает `MANA.exe --cli`.

### Мозги

Мозг без ключа просто отсутствует в пуле. Ключи хранятся в Windows Credential
Manager или в переменных окружения — никогда в файлах и в репозитории.

| Мозг | Переменная | Доступ |
|---|---|---|
| `ollama` | — | локально |
| `groq`, `groq-qwen` | `GROQ_API_KEY` | бесплатный тариф |
| `gemini` | `GEMINI_API_KEY` | бесплатный тариф AI Studio |
| `cerebras` | `CEREBRAS_API_KEY` | бесплатный тариф |
| `mistral` | `MISTRAL_API_KEY` | бесплатный тариф |
| `github-models` | `GITHUB_TOKEN` | любой GitHub PAT |
| `openrouter-free`, `openrouter-alt` | `OPENROUTER_API_KEY` | модели `:free` |
| `lmstudio` | — | локальный OpenAI-совместимый сервер, `MANA_ENABLE_LMSTUDIO=1` |
| `cloudflare` | `CLOUDFLARE_API_TOKEN` + `MANA_CLOUDFLARE_ACCOUNT_ID` | Workers AI |
| `deepseek`, `openai`, `openrouter` | соответствующие ключи | платно, выключены по умолчанию |

Кроме языковых моделей в пуле есть алгоритмические мозги (`mana/substrates.py`):
точная арифметика через AST и исполнение кода в песочнице — без модели.

Локальную модель окно предлагает поставить само, подобрав размер под машину
по **измеренной** полосе памяти (скорость декодирования ≈ полоса / размер).
По умолчанию берётся самая крупная из *удобных*, а не из влезающих. Ничего не
ставится без нажатия кнопки.

## Что агент умеет на этой машине

| Возможность | Чем обеспечена | Что умеет |
|---|---|---|
| `docx` / `xlsx` | python-docx, openpyxl | чтение и запись без установленного Office (формулы не пересчитываются) |
| `editor` | Notepad++ | открыть файл на нужной строке |
| `onec` | pywin32 + `V83.COMConnector` | запросы к 1С:Предприятие 8, запись только с подтверждением |
| `onec_client` | `1cestart.exe`, `1cv8.exe` | запуск 1С, вход в базу по имени, создание базы |
| веб | `ddgs` | поиск с повторами и circuit breaker |
| память | SQLite WAL + FTS5, граф реплик | вспомнить сказанное и записанное |

Что доступно прямо сейчас, агент говорит сам: `capabilities_status()`
(`mana/capabilities.py`) перечисляет инструменты с их доступностью и мозги с
готовностью и измеренной надёжностью. Мозг, которого ни разу не вызывали, —
«не измерено», а не ноль.

**Просьба выполняется, а не пересказывается.** «Открой Notepad++» и
«Запусти 1С» распознаются сопоставлением (`mana/apps/intent.py`), без модели,
и вызывают инструмент. Ответ строится из исхода: «не найден Notepad++» —
честный ответ, «открываю» без открытого окна — ложный. Вопрос «как открыть
Notepad++?» намеренно не запускает программу.

**Запись в 1С — двухшаговый протокол.** `onec_propose_write` читает текущие
значения и ничего не пишет; человек видит «было → стало» и подтверждает;
`onec_confirm_write` — единственный путь к записи. Заявка живёт 5 минут, перед
записью значения перечитываются, и если база изменилась — отказ вместо
затирания. Флага «разрешить запись на сессию» нет намеренно.

**Пароль 1С.** 1С принимает его только в командной строке (`/N`, `/P`), а
командную строку процесса может прочитать любая программа, запущенная от вашего
имени. Поэтому каждый запуск с паролем возвращает `warning`, пароля нет в
ответах и логах; без пароля 1С спросит его своим окном. Учётные данные
(`MANA_1C_CONNECT`, `MANA_1C_USER`, `MANA_1C_PASSWORD`) — в Credential Manager.

## Как устроено сейчас

Путь запроса пользователя (окно `mana_desktop/session.py`, терминал
`cli.py` → `ManaAgent.solve_task`):

```text
запрос
  └─ plan_task — одно решение на ход, до исполнения     agent_parts/planning.py
        уточнить / запомнить / действие программе / ответ
        для ответа: маршрут local/web/mixed, путь, граф узлов, стратегия мозгов
  ├─ уточнение, «запомни»                               agent_parts/core.py
  ├─ действие программе                                 apps/intent.py → apps/tools.py
  └─ answer(task, PipelineSpec, plan)
        граф MEMORY → WEB → LLM → CRITIC → REPAIR → SYNTHESIS → EXECUTE
        проверка: арифметика, песочница, критик         verifier.py, execution.py
  после хода:
        журнал эпизода + objective-отказы → реестр находок     journal.py, cognition/observed.py
        разрыв способности → реестр находок                    cognition/gaps.py
```

План едет на результате хода (`result["plan"]`), поэтому видно, почему ход был
обслужен именно так. Адаптивный цикл может менять стратегию мозгов от шага к
шагу; что использовано на каждом шаге — в трассе.

| Слой | Где | Строк |
|---|---|---|
| Агент (9 миксинов `ManaAgent`) | `mana/agent_parts/` | ~4 200 |
| Ресурсы агента: мозги, инструменты, память, проверка, способности, конфиг | `brains.py`, `tools.py`, `capabilities.py`, `memory.py`, `graph_memory.py`, `verifier.py`, … | ~5 700 |
| Программы на машине | `mana/apps/` | ~2 900 |
| Окно | `mana_desktop/` | ~1 700 |
| Неизменяемое ядро приёмки | `mana/core/` (gates, splits, transaction, evaluation, oracle, tasks) | ~2 400 |
| Лаборатория самоулучшения | `mana/cognition/` без шахмат, `mana/world/` | ~15 700 |
| Шахматный полигон | `mana/cognition/chess_*.py`, `mana/net/lichess.py`, `aichess.py` | ~7 000 |

**`PipelineSpec`.** У каждого поля объявлен владелец (`pipeline.FIELD_ROLES`):
способности (`use_web`, `use_memory`, …), маршрутизация (`route_mode`,
`brain_policy`, …), профиль исполнения LLM (`temperature`, `prompt_strategy`,
`graph_nodes`, …) и конфигурация (`memory_top_k`, `max_context_chars`, …).
Эволюция двигает только профиль исполнения. Физически это пока один класс:
все читатели обращаются к `spec.<поле>`. Поля `verification_mode` и
`web_provider` удалены — первое читал только отчёт, второе никто. Состояния и
записи опыта, сохранённые старыми версиями, загружаются
(`PipelineSpec.from_dict`).

## Самоулучшение

| Механизм | Как запускается | Влияет на ответы пользователю |
|---|---|---|
| Реестр находок: отказ в реальной работе записывается сам | после каждого хода | косвенно — через кандидатов ниже |
| Разрыв способности: команда программе не выполнена, ответ опровергнут проверкой и не исправлен, ответ без мозга — записывается с тем, что его закрыло бы | после каждого хода | нет — это вход для самоулучшения |
| Кандидаты изменений → ручки `policy.py` → приёмка | `--propose`, вкладка «Опыт» | да, принятые ручки читаются при ответе |
| Эволюция `PipelineSpec` | кнопка в окне, `/improve`, `--cycles` | да. Кандидатов отбирает по 21 подстрочной задаче, **принимает только `core/gates`** на 36 задачах с оракулом и скрытой выборке; прежние проверки остались правом вето |
| Правка собственного кода с откатом | `--self-improve-code`, `--rollback-code` | через `core/gates`. У целей по 5–10 тест-кейсов и нет скрытой выборки, поэтому ворота отвечают NOT_EVALUATED: патч сейчас принять нельзя |
| Законы, серии, выбор следующей оси | `--laws`, `--series`, `--next` | законы — только через `acting`, из CLI |
| Модель себя, curriculum, программы мышления, исследовательский цикл | скрипты и CLI | нет |
| Шахматный полигон (ниже) | `mana.cmd --bench` | нет — это доказательная среда |

Вердикт трёхзначный: `ACCEPTED` / `REJECTED` / `NOT_EVALUATED` («не измерено» —
не ноль). `mana/core/gates.py` — единственное место, где можно сказать
«принято»: теперь и для эволюции конвейера, и для правки кода. Скрытая выборка
никогда не возвращается как данные и солится ключом установки. Каждая адопция
конвейера и каждый применённый патч — транзакция (`core/transaction.py`), и
прерванная находится после сбоя.

## План миграции к агенту

Цель: `USER → AGENT → TASK → CAPABILITIES / TOOLS / BRAINS → RESULT`, а
самоулучшение подключается, когда агент упирается в разрыв способности:
`AGENT → GAP → SELF-IMPROVEMENT → NEW CAPABILITY → AGENT`. Без переписывания
с нуля: каждая фаза закрывается своим тестом.

| Фаза | Что даёт | Файлы | Что не трогали | Тест | Статус |
|---|---|---|---|---|---|
| 1. Реестр способностей | одно место: что агент может использовать сейчас | `capabilities.py`, `agent_parts/core.py` | путь ответа, `PipelineSpec`, лабораторию | `tests/test_capabilities.py` | сделано |
| 2. Планировщик и владельцы полей `PipelineSpec` | одно решение на ход; эволюция двигает только профиль исполнения | `agent_parts/planning.py`, `pipeline.py`, `core.py`, `execution.py`, `routing.py`, `evolution.py`, `experience.py` | внутренности мозгов и инструментов, приложения, лабораторию, шахматы | `tests/test_planning.py` | сделано |
| 3. Хук AGENT → GAP | ход, который агент не смог обслужить, записывается с тем, что его закрыло бы | `cognition/gaps.py`, `agent_parts/core.py` | приёмку, эволюцию | `tests/test_capability_gaps.py` | сделано |
| 4. Одни ворота для всего, что меняет агента | эволюцию и правку кода судит `core/gates`; адопции — транзакции | `agent_parts/evolution.py`, `code_evolution.py`, `tests/conftest.py` | поиск GA, планировщик | `tests/test_acceptance_gates.py` | сделано |
| 5. Петля с отложенным исходом в Core; шахматы — адаптер | общие механизмы полигона (вердикт дуэли, reach, адопция с подтверждением, выбор опыта) переезжают в Core, шахматы оставляют себе правила, игрока и транспорт | `chess_*`, `policy.py`, `lessons.py`, `core/gates.py`, `investigator.py` | `SearchPlayer`, `SCORERS`, Lichess, лестницу, окно наблюдения | путь Core воспроизводит реальные вердикты и reach полигона | не начата |

Что после фаз 1–4 остаётся нерешённым:

- **Разрыв записывается, но новая способность по нему не строится.**
  `brain_factory` называет класс механизма, дальше пока ничего не происходит.
- **Правку кода ворота сейчас не пропустят.** Нужны цели с 30+ тест-кейсами и
  отложенная выборка для патчей.
- **Эволюция `PipelineSpec` стала дороже.** Кандидат, прошедший предварительный
  отбор, отвечает на 36 задач и дважды на скрытую выборку в каждом плече;
  бюджет скрытой выборки — 50 оценок на процесс.
- **`PipelineSpec` пока один класс.** Владельцы полей объявлены и соблюдаются
  эволюцией, но физически он не разделён.

## Шахматный полигон

Не цель продукта, а среда, где механизм самоулучшения проверяется на мире с
отложенным исходом: ход сейчас, результат через десятки ходов, соперник.

```bash
mana.cmd --chess 30             # самоигра, партии записываются
mana.cmd --lichess-token        # ввести токен Lichess (в Credential Manager)
mana.cmd --lichess 1            # принять вызовы на Lichess
mana.cmd --bench                # лестница против Stockfish + опыты в паузах
mana.cmd --chess-experiment 70  # один причинный опыт вручную
mana.cmd --aichess ИМЯ          # регистрация на AI Chess Arena — запускает пользователь
```

Лестница: с уровня 1, 10 побед подряд — следующий уровень, 30 подряд на 8 —
конец, ничья серию сбрасывает. Пока Lichess держит паузу после 429, MANA
играет сама с собой и ставит опыты. Окно наблюдения — только на `127.0.0.1`.
Перевод аккаунта в BOT необратим и делается пользователем.

Цепочка, которая здесь реально замкнута:

```text
партия → наблюдаемые (без движка и порогов) → находка по исходу
      → изменение: выбор среди равноценных ходов по свойству
      → reach: изменило бы оно хоть один ход (без партий)
      → дуэль с игроком без изменения → ACCEPTED / REJECTED / NOT_EVALUATED
      → принято условно → подтверждение на свежих партиях → в силе или откат
```

Итог на составе `v0-base`: из 13 наблюдаемых свойств 7 годятся для действия;
5 опровергнуты причинно, 2 ничего не двигают. Когда объявленные рычаги
кончаются, строятся составные («A, при равенстве — B»; 18 из 42 допущены,
первый проверенный отвергнут) и выученная из записи оценка
`learned_outcome` (reach 400 из 400, дуэлью ещё не проверена). Ни одно
изменение пока не принято — это результат, а не сбой.

## Безопасность и границы

- Ключи API, токен Lichess, ключ AI Chess Arena, учётные данные 1С — только
  Credential Manager или переменные окружения.
- `mana_desktop.server` слушает только `127.0.0.1` и никогда `0.0.0.0`: он
  исполняет код в песочнице и пишет в боевую базу 1С.
- Тесты не подключаются к боевой базе 1С на этой машине и не пишут в данные
  установки: реестр находок, журнал транзакций, версии игрока, запись партий
  изолированы автоматически.
- Ничего не устанавливается по собственной инициативе агента.
- Удаление памяти пользователя — только с явного согласия.
- Зерно скрытой выборки выводится из **закрытого** ключа установки.

## Обмен между установками

Через мост едут **гипотезы, а не вердикты**: получатель строит кандидата от
своего родителя и судит своими воротами. Установка идентифицируется парой
ключей Ed25519; узлы признаются вручную, как в `known_hosts`.

```bash
MANA.exe --exchange export обмен.json
MANA.exe --exchange import обмен-от-коллеги.json
MANA.exe --peer serve                     # отдельная точка, 0.0.0.0:8787, три маршрута
MANA.exe --peer sync 192.168.0.5:8787
```

`--peer serve` — намеренно отдельный сервер без агента, песочницы и 1С. Порядок
проверки на второй машине — [docs/ОБМЕН_МЕЖДУ_УСТАНОВКАМИ.md](docs/ОБМЕН_МЕЖДУ_УСТАНОВКАМИ.md).

## Разработка

```bash
python -m pytest -q tests/test_planning.py       # отдельный файл — быстро
python -m pytest -q                              # весь набор: около 2 000 тестов, идёт часами
```

Весь набор сейчас идёт в разы дольше суммы своих частей; причина не
установлена. Для проверки изменения гоняются затронутые файлы, весь набор — по
возможности перед выпуском.

Версия продукта объявлена в одном месте — `mana/version.py`; каждая
подсистема версионируется отдельно и поднимается вместе с изменением.
`tests/test_versioning.py` падает, если продуктовая версия изменилась без
обновления теста.
