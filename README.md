# MANA 2.26.0

Самоулучшающийся когнитивный агент. Работает локально на Windows: как
приложение с окном, как команда в терминале и как библиотека.

> **Номер версии пошёл назад — с 5.25.0 на 2.0.0, намеренно.** Линия 5.x
> нумеровала одномозгового агента поверх LLM, который рос наращиванием.
> Сейчас работает другая система: неизменяемое ядро, владеющее
> генератором задач, оракулом, скрытой выборкой и гейтами приёмки, и
> эволюционирующий когнитивный слой, который предлагает изменения, а ядро по ним
> выносит вердикт. Продолжать счёт с 5.25 значило бы утверждать, что второе —
> это поздний релиз первого. Все 56 модулей получили 2.0 одновременно:
> поколение — свойство системы, а не отдельной подсистемы. Внутри
> репозитория версии нигде не сравниваются численно, это строки для
> отображения; но всё, что снаружи упорядочивает релизы, прочтёт 2.0.0
> как более старое, чем 5.25.0 — это цена перенумерации.

Проект перестроен из «агента поверх LLM» в **открытую когнитивную
систему** — такую, которая может расширять пространство собственных
представлений, операторов и программ мышления, а не только перебирать
параметры внутри заданного пространства.

Центральный вопрос, на который проект должен ответить экспериментально:

> Может ли автономная когнитивная система сама обнаружить новый способ
> мышления, проверить его на независимых задачах, доказать преимущество,
> перенести на другой домен и встроить как часть собственной архитектуры?

Это **гипотеза, а не результат.** Ниже честно разделено, что уже
измерено, а что пока только построено.

## Быстрый старт

```bash
pip install -r requirements.txt

python mana_run.py --list-brains          # какие мозги готовы и чего не хватает
python mana_run.py --ask "Сколько будет 17 * 23?"
python mana_run.py --consensus 2 --ask "..."   # два мозга + степень согласия
python mana_run.py --decompose "..."      # разбить, решить на разных мозгах, собрать
python mana_run.py --paths-status         # где лежит состояние и песочница
python mana_run.py --interactive
```

Приложение с окном:

```bash
python serve_ui.py                    # интерфейс в браузере, без сборки
python build_exe.py --windowed        # собрать MANA.exe
dist/MANA/MANA.exe --self-check       # проверить, что упаковка ничего не сломала
python scripts/build_installer.py     # установщик (нужен Inno Setup 6)
```

Сборка сверяет окружение со списком `packaging_deps.BUNDLED` и
останавливается, если пакета нет. Это не педантизм. `ddgs` и `psutil`
были названы в `requirements.txt`, обёрнуты в `try/except` и не
установлены на сборочной машине: PyInstaller молча не клал их в пакет,
сборка печатала «Готово», `--self-check` проходил все свои проверки, а
веб-поиска в приложении не было ни у кого. Тот же `try/except` правилен
во время работы — он и позволяет MANA деградировать вместо падения — и
неверен во время сборки, где он превращает «пакета нет» в тишину.

`--self-check` внутри упакованного приложения проверяет теперь не только
импорт пакета, но и флаги возможностей (`HAS_SKLEARN`, `HAS_WEB`,
`HAS_FITZ`): `import sklearn` и `from sklearn.feature_extraction.text
import TfidfVectorizer` — разные утверждения, а нужно второе.

Установщик ставит MANA в `%LOCALAPPDATA%\Programs\MANA` без прав администратора.
Иначе нельзя: приложение переписывает собственный код, а в Program Files
каталог установки недоступен ему на запись — самопатчинг падал бы на
правах доступа, и падал бы молча. Память агента (`%LOCALAPPDATA%\MANA`)
при удалении сохраняется.

Мозги подключаются бесплатными ключами; мозг без ключа просто отсутствует
в пуле. `--list-brains` показывает, где именно взять недостающий.

| Мозг | Переменная | Доступ |
|---|---|---|
| `ollama` | — | локально |
| `groq`, `groq-qwen` | `GROQ_API_KEY` | бесплатный тариф, ключ вида `gsk_...` |
| `gemini` | `GEMINI_API_KEY` | бесплатный тариф AI Studio |
| `cerebras` | `CEREBRAS_API_KEY` | бесплатный тариф |
| `mistral` | `MISTRAL_API_KEY` | бесплатный тариф |
| `github-models` | `GITHUB_TOKEN` | любой GitHub PAT |
| `openrouter-free`, `openrouter-alt` | `OPENROUTER_API_KEY` | модели с суффиксом `:free`, разных семейств |
| `lmstudio` | — | локальный OpenAI-совместимый сервер, `MANA_ENABLE_LMSTUDIO=1` |
| `cloudflare` | `CLOUDFLARE_API_TOKEN` + `MANA_CLOUDFLARE_ACCOUNT_ID` | Workers AI |
| `deepseek`, `openai`, `openrouter` | соответствующие ключи | платно, выключены по умолчанию |

Веб-интерфейсы ChatGPT и DeepSeek намеренно не используются: это нарушает
условия провайдеров, ломается при каждом редизайне и ведёт к блокировке
аккаунта. Каждый мозг обращается к документированному API.

### Почему граница именно такая

MANA не должна иметь возможности улучшить себя, изменив механизм, который
объявляет её улучшенной. Это не формальность: аудит показал, что до
перестройки инвариант держался **случайно** — `BenchmarkSuite` жил в
`pipeline.py`, который ничто не защищало, и только то, что whitelist
самопатчинга содержал одну чистую функцию, удерживало агента от
собственного тестового набора.

Поэтому:

- `mana/core/` защищён **по каталогу**, а не по списку имён: файл,
  положенный туда, защищён с момента появления;
- функции `hidden_tasks()` **не существует** — единственный способ
  соприкоснуться со скрытым набором это `hidden_score(answer_fn)`,
  возвращающий агрегаты; задачи живут только внутри вызова;
- обращения к скрытому набору считаются, ограничены бюджетом и
  логируются: неограниченные запросы подгоняют скрытый набор через один
  только счёт;
- режим оценки выдаётся ядром и не может быть присвоен агентом.

**Честное ограничение**, записанное в самих модулях: в Python нет
приватности, решительный патч подделает что угодно. Граница даёт то, что
её пересечение — явное действие, попадающее в запись, а не однострочное
присваивание, выглядящее как обычное состояние.

| После исправления | тот же вопрос: мозг `arithmetic`, **0 токенов**; 40/40 на всех трёх поверхностях сохранилось |
| **Дефект: отказы съедали бюджет попыток** | пять дешёвых мозгов исчерпывали три попытки отказами, и языковая модель становилась недостижимой — добавление дешёвого субстрата молча ухудшило бы всё, что он не умеет |
| **Дефект, найденный живым прогоном на чужой машине** | с экспортированным `GROQ_API_KEY` четыре «офлайновых» теста уходили в облако и падали; под голым `pytest` проходили. Набор тестов не был герметичен относительно окружения |
| **Дефект: одно поле, два значения в одном ответе** | `trace.verification_trust` оставался `UNVERIFIED` после того, как верификатор поймал и исправил неверный ответ, а вердикт рядом говорил `INDEPENDENTLY_VERIFIED` |
| **Дефект: окно перестало быть окном** | поле чата выросло до 39 622 px внутри окна 800 px, прокрутки не было, композер уехал за нижнюю границу — во всей цепочке grid→flex не хватало `min-height: 0` |
| Сборка `.exe` | песочница, самопатчинг и память живы в упакованном приложении |

Два результата стоит выделить отдельно, потому что они **отрицательные**,
и в этом их ценность:

- цикл с критиком проиграл прямой цепочке (0.33 против 0.50) при тройной
  стоимости, и ворота отклонили его по шести пунктам;
- при 10 наблюдениях лаборатория выдала **ноль гипотез**, корректно
  отказавшись предлагать механизмы для того, что ещё не измерено.

Аппарат существует ровно затем, чтобы такие вещи не проходили.

Плюс счётчик активации: эксперимент, где параметр не прочитан или прочитан и отброшен, объявляется не результатом, а отказом судить.

- [x] **Фаза 23.1 — Три сценария запуска 1С.** Окно выбора базы; запуск конкретной базы с логином; создание базы, где отказ без пути и есть вопрос «где разместить». Языковой модели контекст нужен — он и делает ответ хорошим; точному механизму он ровно вреден, потому что тот отвечает точно или отказывается, а точным он может быть только про сам вопрос. Арифметика при этом не потерялась: `Вычисли: 4821 * 37 + 145` по-прежнему решается за 0.001 с и ноль токенов, но из 24 символов вместо 5181.
- [x] **Фаза 22 — Пакет несёт то, что обещает.** Манифест зависимостей вместо `try/except` на этапе сборки; сборка останавливается, если пакета нет, и пишет `build_manifest.json` рядом с исполняемым файлом. `sklearn`, `scipy` и `fitz` убраны из исключений: их исключение не спасало пользователя от 3 ГБ, а вырезало обученный роутер, семантический поиск и чтение PDF. Установщик Inno Setup ставит в каталог пользователя, потому что самопатчингу нужны права на запись. Значок в трее: закрытие окна больше не убивает идущий цикл.
- [x] **Фаза 21 — Пространство описаний перестало быть списком.** Пороги выбираются из самих коллизий, а не автором; поле «какой дешёвый механизм берёт задачу» — ось, которой в списке быть не могло. Каждое поле выводится на половине наблюдений и оценивается на другой; ранжирование по отложенной половине, иначе подгонка невидима.
- [x] **Окно как инструмент наблюдения.** Под каждым ответом — чем он обошёлся в реальных единицах и какой субстрат отвечал. Когнитивный цикл запускается из окна, шаги идут в журнал, профиль способностей показан интервалами. Вкладка генома читает сохранённое, а не строит базовое.
- [ ] **Финальный приёмочный эксперимент.** Полная цепочка с перезапуском и проверкой, что найденная способность сохранилась.

### Журнал эпизодов — что MANA на самом деле сделала

`mana/journal.py`. На каждый ход пользователя пишется запись: запрос,
**какие инструменты реально были вызваны и с каким исходом**, и что было
отвечено. Смотреть — `MANA.exe --journal` (или `python mana_run.py
--journal 50`).

**Зачем.** `Observation` — единственное, что может попасть в самомодель —
создаётся ровно в двух местах, и оба внутри `cognition/curriculum.py`, из
задач `core/tasks.py` с вычисленными ответами. То есть весь аппарат
самоулучшения (ResearchCycle, `choose_mechanism`, геном, приёмочные
ворота, скрытый холдаут) направлен на пять синтетических доменов, а все
дефекты из реальной работы живут в слое между человеком и инструментами —
и этот слой не производил ни одного наблюдения.

Замерено до появления модуля: трасса вызовов не писалась нигде. Текст
ответа уходил в память, список вызванных инструментов — никуда. Именно
поэтому «Открой Notepad++» мог ответить «Открываю Notepad++.» при нуле
вызовов и не оставить следа: единственный факт, который делает этот отказ
машинно-обнаружимым, был единственным, который никто не записывал.

**Границы, проведённые намеренно:**

- Журнал **ничего не судит**. Он не решает, хорош ли ход, не блокирует
  ответ и не кормит самомодель. Обнаружение противоречия между «открываю»
  и пустым списком вызовов — отдельный шаг со своими решениями; встроить
  его в запись значило бы позволить его собственным ошибкам молча
  переписывать улики.
- **Аргументы инструментов не пишутся вообще.** Это поле с наибольшей
  вероятностью несёт пароль и с наименьшей отдачей для инвариантов.
- Запрос и текст ошибки проходят через `scrub()` до записи на диск.
  «Мана запусти 1С базу UT11-ER логин Иванов пароль ...» — один из трёх
  сценариев 1С, которые проект обязан поддерживать, то есть обычная
  работа, а не редкий случай.
- Открытый эпизод — **на поток**. Фоновый цикл исследований, вызывающий
  инструменты, пока человек печатает, не должен приписывать свою работу
  его ходу.
- Журнал не может уронить ход. Ошибка записи проглатывается: улики,
  способные сломать то, за чем наблюдают, не стоят того.
- Ротация — 8 МБ, текущий файл плюс один предыдущий. Это десятки тысяч
  ходов; что теряется — история многолетней давности.

**Чего это ещё не даёт.** Журнал накапливает материал, но никакой вывод
из него пока не делается. Следующий шаг — один инвариант в теневом
режиме («ответ утверждает действие, а вызовов не было»), чтобы измерить
долю реальных отказов, которые вообще машинно-обнаружимы. Пока эта доля
не измерена, порождение доменов из эпизодов строить рано.

### Инварианты — MANA находит свои отказы сама

`mana/cognition/invariants.py`. Предикаты над записанным эпизодом,
которые называют отказ, **никого не спрашивая**. Смотреть —
`MANA.exe --findings`.

**Асимметрия, снимающая кажущийся замкнутый круг.** Возражение
очевидное: «MANA не может понять, что должна была запустить 1С — это же
ровно тот матчер, который не сработал». Верно для **исполнителя** и
неверно для **детектора**:

- `mana/apps/intent.py` обязан быть узким. Ложное срабатывание там
  запускает программу тому, кто задал вопрос.
- Детектор может быть широким. Ложное срабатывание здесь стоит одной
  строки в отчёте, который читает человек.

Поэтому детектор — намеренно расширенный двойник исполнителя, и
**разрыв между ними и есть измерение**: каждый эпизод, где широкий
детектор сработал, а узкий исполнитель ничего не сделал, — кандидат в
отказы. Это обобщается: для любого узкого механизма более широкий
теневой двойник измеряет, что механизм упускает.

**Два рода вердикта, никогда не смешиваются.** `mechanical` решается
сравнением записанных полей — воспроизводимо, без мнения о смысле.
`pattern` опирается на список слов и является догадкой. Подать догадку
как факт — ровно тот отказ, который проект чинит снова и снова, поэтому
род путешествует с каждым нарушением, и всё, что позже будет делать из
находок учебный материал, вправе брать только `mechanical` без
подтверждения человеком.

**Три инварианта на сегодня:**

- `repeats_earlier_answer` (`mechanical`) — ответ повторяет ответ,
  данный ранее **в этой сессии**, на другой вопрос. Отличие от живого
  `echo_guard`: тот сравнивает только с непосредственно предыдущим
  ходом. Замерено: ответ, идентичный данному тремя ходами раньше,
  набрал 1.00 против того хода и 0.018 против того, который guard
  смотрит, — и прошёл.
- `claimed_action_without_acting` (`pattern`) — ответ утверждает
  действие от первого лица, но ни один инструмент действия не отработал.
  Инфинитивы исключены: «вы хотели запустить» описывает просьбу,
  «запускаю» заявляет поступок.
- `actionable_request_not_acted_on` (`pattern`) — просьба сделать
  что-то на этой машине, и ничего не сделано. Глагол где угодно в
  сообщении (а не в начале, как требует исполнитель), имена баз
  сопоставляются по основам слов, так что «конфигуратор информационной
  базы» достаёт до «Информационная база».

**Замерено на первых семи реальных ходах:** 3 нарушения в 3 эпизодах,
ложных срабатываний ноль. Один ложноположительный найден тестами («как
запустить 1С на новом компьютере?» — вопрос *про* действие) и исключён
по вопросительному слову в начале; на вопросительный знак сам по себе
исключать нельзя — «Можешь запустить 1С?» это настоящая просьба.

**Чего инварианты не поймали, и почему:**

- «Привет, Мана» → рассказ про погоду в Воронеже. Ответ пришёл из
  памяти сессий, бывших **до** появления журнала, — сравнивать не с чем.
  Журнал не видит прошлого; это лечится только накоплением.
- «почему ты не можешь этого сделать?» → «Вы уже получили рецепт
  хот-дога». Это не повтор (текст другой), а **нерелевантный** ответ.
  Требует суждения о смысле и механически пока не решается. Класс
  остаётся вне досягаемости, и делать вид иначе — то же враньё про
  действие, только уровнем выше.

**Теневой режим — это весь аргумент безопасности.** Модуль ничего не
меняет в ответе, не блокирует ход и не кормит самомодель; он читает уже
записанное. Есть тест, который падает, если в модуле появится вызов
реестра инструментов, `solve_task`, `answer` или `subprocess`.

**Чего это ещё не даёт: находить — не значит чинить.** Инварианты
производят находки, а не исправления. Следующий шаг — превратить набор
нарушений одного инварианта в домен с оракулом, чтобы к нему стал
применим существующий аппарат (`choose_mechanism`, геном, приёмочные
ворота, скрытый холдаут). Пока этого нет, находки читает человек.

### Домен отказов — находки становятся измеримыми

`mana/cognition/failure_domain.py`. Замыкающее звено цепи:

```
journal.py       что ход реально сделал            (улики)
invariants.py    какие ходы себе противоречили     (находки)
failure_domain   находки → домен с оракулом        (измеримо)
core/gates.py    ACCEPTED / REJECTED / NOT_EVALUATED  (уже было)
```

**Оракул — это инвариант.** У задач `core/tasks.py` есть вычисленный
ответ, и чекер сравнивает с ним. У записанного отказа такого ответа нет:
никто не знает единственно верную реплику на «запусти конфигуратор».
Зато точно известно, чего реплика делать **не должна**: противоречить
себе, повторять прошлый ответ, заявлять действие, которого никто не
совершал. Поэтому ситуация считается пройденной, если ни один инвариант
не сработал.

**Одно испытание на ситуацию, а не на инвариант.** Три инварианта на
одном эпизоде — не три независимых наблюдения; McNemar по ним раздул бы
выборку и купил бы значимость, которой нет. Инвариант, первым
пометивший ситуацию, становится её `domain` — и существующий гейт
`no_regression` бесплатно делает межинвариантную проверку.

**Вердикт выносят существующие ворота.** Модуль — переходник, а не
второй набор ворот: порог выборки, McNemar, допуск на регрессию,
подтверждение на скрытой части, три состояния — всё в `core/gates.py`,
которое уже работает для синтетических доменов и уже покрыто тестами.
Свой судья позволил бы домену отказов принимать на более лёгких
условиях, чем всё остальное.

**Скрытая часть солится** через `identity.salted_seed` от приватного
ключа, как и все остальные холдауты, и разбиение стратифицировано: при
таких выборках несбалансированный жребий регулярно оставляет в скрытой
части одни здоровые ходы, а такая часть подтверждает что угодно.

#### Дыра, найденная запуском, и чем она закрыта

Первая версия её имела. Замерено на семи реальных ходах: ответчик,
отвечающий «Не знаю.» на всё, набрал **0.8 против базовых 0.6**,
здоровые ходы не тронул, контрпримеров не дал — при тридцати испытаниях
вместо пяти он прошёл бы все ворота и был бы **принят**.

Это не низкий порог. **Все инварианты отрицательные**: каждый говорит,
чего ответ делать не должен, а молчание не делает ничего из этого.
Чисто отрицательный оракул максимизируется молчанием, и никакая
настройка формы не меняет.

Закрыто вторым способом сломать: `counterexamples` теперь считает не
только «ситуация проходила, а теперь падает», но и «базовая версия
ответила по существу, а кандидат отвечает штампованным отказом».
Вырождение в молчание проваливает гейт контрпримеров вместо того, чтобы
выигрывать на остальных.

#### Что это НЕ даёт

Оракул от этого не стал положительным. Отличить полезный ответ от
правдоподобно-неверного здесь нечем — релевантность механически не
решается.

Отсюда архитектурное правило, а не заплатка: **домен отказов — это
дополнительные ворота, но никогда не достаточные.** Изменение можно
принять по нему только если оно держится и на синтетических доменах, у
которых есть вычисленные ответы. Измерить «перестала себе противоречить»
— не то же самое, что измерить «отвечает хорошо». Есть тест, который
падает, если эта оговорка исчезнет из модуля.

#### Проверено на живой цепочке

- 7 реальных ходов → REJECTED по `sample_size`. Это верный ответ, а не
  дефект: три помеченных хода — не свидетельство ни о чём.
- Молчун → REJECTED по `counterexamples`.
- Настоящее исправление на 60 ситуациях → **ACCEPTED**: 42 испытания,
  p = 1e-6, скрытая часть подтверждает, здоровая группа без изменений,
  контрпримеров ноль. Конвейер, умеющий только отвергать, неотличим от
  сломанного, поэтому это проверяется отдельно.

### Генератор кандидатов — MANA предлагает изменения себе

`mana/policy.py` + `mana/cognition/candidates.py`. Замыкает круг:

```
journal.py       что ход сделал              улики
invariants.py    что пошло не так            находки
failure_domain   находки → домен с оракулом  измеримо
candidates.py    находки → что менять        кандидаты
core/gates.py    вердикт                     уже было
```

Смотреть — `MANA.exe --propose`.

**Что именно изменилось в подходе.** Код исправлений никуда не делся:
«повелительный глагол может стоять в середине» — это по-прежнему строчка
кода. Но два решения ушли из мнения в измерение: **какое** изменение
пробовать и **оставлять ли** его.

#### Поверхность, на которую действуют кандидаты

`mana/policy.py` — маленький явный набор точек решения, которые путь
ответа действительно опрашивает. Аллоулист: поле, не объявленное там,
кандидат изменить не может, как бы предложение ни было написано — та же
причина, по которой `brain_factory` вправе собирать кандидатов и не
вправе их принимать.

**Все умолчания — сегодняшнее поведение**, поэтому импорт модуля ничего
не меняет. Политика действует **на поток**: цикл, оценивающий кандидата,
работает, пока человек печатает, и общий на процесс переключатель молча
отвечал бы на его вопрос под непроверенной политикой.

Шесть точек решения на сегодня: глубина сравнения для эха и два его
порога; где может стоять глагол; какие формы глагола считать просьбой;
сопоставлять ли имена баз по основам. Каждая объявляет, на какой
инвариант влияет.

#### Как берётся прицел

Кандидат предлагается **только** для инварианта, который реально
сработал на записи. Нет наблюдённого отказа — нет кандидата. Слепая
мутация по пространству политики истратила бы весь бюджет на изменения,
которые ничего не адресуют, и трясла бы работающую систему.

`policy.knobs_for(invariant)` — то, чем берётся прицел: каждая точка
решения объявляет, на что влияет, поэтому предложение связано с
измерением по построению, а не по вере предлагающего.

По одной настройке за раз плюс одна комбинация. Полный перебор — 288
политик на шесть точек, столько не оплатит никакой бюджет, а принятая
комбинация не сказала бы, какая её часть сработала.

**`choose_mechanism` решает, уместна ли настройка вообще.** Для обоих
найденных инвариантов ответ `algorithmic`: обнаружить повтор — точно,
сопоставить имя со списком баз — точно. Домену с вычислимым ответом не
нужна модель, которая его приближает. Если для какого-то инварианта
ответ окажется `classical_ml` или `keep_model`, модуль не предложит для
него ничего и скажет почему: иначе поиск начнёт улучшать то, что умеет
крутить, вместо того, что сломано.

#### Сухая оценка и чего она не вправе утверждать

`dry_responder` отвечает на записанную ситуацию под политикой-кандидатом
**без модели и ничего не выполняя**: спрашивает матчер, что бы он сделал,
спрашивает прикладной слой `would_act`, выполнимо ли это, и строит
ответ так же, как живой путь — из исхода.

Она предполагает, что выполнимое действие удаётся. 1С может быть
установлена, база может существовать, а запуск всё равно сорваться.
Поэтому сухая оценка — **верхняя граница**, помечена как таковая, и
воротам её никогда не подают под видом измерения настоящего.

Настройки эха всухую не оцениваются вовсе и **отклоняются, а не
угадываются**: когда guard срабатывает, живой путь делает повторную
попытку с подавленным контекстом, и что она ответит, без модели
неизвестно. Число там было бы выдуманным свидетельством.

#### Что MANA предложила себе по собственной записи

Семь ходов, три нарушения → **12 кандидатов**, лучший:

```
0.57 -> 0.86  (+0.29, сломано: 0)
  менять:  intent_stem_match=True, intent_verb_anywhere=True,
           intent_verb_forms='addressed'
  целит в: actionable_request_not_acted_on  (2 нарушения)
```

Под этой политикой обе реально пропущенные просьбы распознаются с
верной базой и режимом конфигуратора, а «Как запустить 1С?» и «ты уже
открыла отчёт?» по-прежнему не распознаются — то, ради чего исполнитель
и был узким.

**Ни одно изменение не применено.** Ранжирование говорит, что стоит
измерить как следует, а не что внедрять; вердикт выносят ворота, и
свидетельств для него пока нет.

### Приобретение способностей — добыть оракул и доказать, что ему можно верить

`mana/acquire.py`. Смотреть — `MANA.exe --capabilities`.

**Различие, ради которого модуль существует.** «Найти правила игры в
интернете и запомнить» звучит как приобретение способности и ею не
является: правила приходят **текстом**, а текст не может сказать,
легален ли Кf3 в позиции. По нему нельзя ни играть, ни учиться, ни
измерять.

Приобрести можно **исполняемый оракул** — то, что отвечает точно, и
тогда у практики, обучения и приёмочных ворот появляется твёрдая почва.

#### Проверка — это и есть суть

Найденная и установленная библиотека — пока никто. Прежде чем на ней
чему-то учиться, она сверяется с истиной, **записанной литералами прямо
в модуле** и никогда не вычисляемой тем, что проверяется. Набор, который
спрашивает библиотеку «ты права?» и верит ответу, не доказывает ничего.

Для шахмат это опубликованные факты: счётчики perft из начальной позиции
(20, 400, 8902, 197281) и из стандартной позиции Kiwipete, которая
существует именно потому, что задействует рокировку, взятие на проходе и
превращение — правила, которые неверный движок и роняет.

Замерено: 11 проверок, глубокая версия считает 197281 и 97862 узла за
1.15 с. Проверка, которая проходит мгновенно и ничего не считает, хуже
отсутствующей, поэтому это отдельно замерено и покрыто тестом.

**И она ловит сломанный движок.** В тестах есть провайдер, неправильный
ровно так, как бывает в жизни — одно спецправило молча отсутствует
(взятие на проходе), и второй, считающий пат матом. Оба отклоняются.
Незаметно неверный движок правил — это **лгущий оракул**: каждое
измерение под ним отравлено, и снизу этого не видно. Хуже, чем никакого,
потому что отказ невидим. Поэтому провайдер, не прошедший проверку,
получает REFUSED и не используется — не «используется с
предупреждением».

#### Три состояния, как и везде

```
VERIFIED   установлен, все проверки против известной истины пройдены
REFUSED    установлен, проверка провалена — использовать нельзя
ABSENT     не установлен; ничего не проверено, ничего не утверждается
```

«Проверили, и оно неверно» и «проверить не смогли» — разные факты.

#### Согласие и аллоулист

Приобрести можно только способность, объявленную в `CAPABILITIES`.
`pip install` исполняет произвольный код на этапе установки, поэтому
система, ставящая что попало, не саморазвивающаяся, а
самокомпрометирующаяся. Согласие обязательно и передаётся явным
параметром: вызов без него **возбуждает исключение**, а не тихо
возвращает ошибку — забывший спросить это дефект, а не ситуация.

В командной строке согласие — отдельное слово, а не диалог, чтобы его не
мог подразумевать скрипт:

```
MANA.exe --acquire chess_rules        показывает план, ничего не ставит
MANA.exe --acquire chess_rules --yes  ставит и сразу проверяет
```

Пакеты кладутся в `<данные>/packages`, а не в каталог программы:
у замороженной сборки нет pip, и её папка целиком заменяется следующим
запуском установщика, что молча отменило бы все приобретения. Путь
добавляется в `sys.path` перед каждой попыткой импорта, поэтому
приобретённое доступно **без перезапуска**.

#### Где заканчивается открытость

Это сознательный потолок, и его стоит назвать прямо:

> **MANA может проверить провайдера против истины, которую ей дали. Она
> не может выдумать достоверную истину для области, которой не знает.**

Для шахмат истина опубликована и независима. Для произвольной новой
области её должен кто-то поставить — а набор проверок, написанный тем же
процессом, который выбрал библиотеку, замкнут сам на себя. Это и есть
честная граница «саморазвития» в том виде, в каком модуль его
реализует. Есть тест, который падает, если эта оговорка исчезнет.

### Среда для практики — самоигра на проверенном движке

`mana/cognition/chess_arena.py`. Смотреть — `MANA.exe --practice`
(без числа — что накопилось, с числом — сыграть столько партий).

**Внешняя программа не нужна.** Играть через чужой GUI значит превратить
чистую задачу в задачу компьютерного зрения: отлаживать распознавание
доски вместо обучения, и тратить секунды экранного скрапинга на каждый
ход. Проверенный движок правил **сам и есть среда** — он порождает
легальные ходы и объявляет мат, пат, повторение и правило 50 ходов,
причём точно, что и установила `acquire.py` до первой сыгранной партии.

#### Отказ, который делает приобретение настоящим

`play` и `self_play` **отказываются работать**, если
`acquire.verify("chess_rules")` не сказала VERIFIED. Не предупреждение —
отказ. Иначе проверка была бы декорацией, а корпус, порождённый на
незаметно неверном движке, неверен так, что снизу этого не увидеть.
Проверено тестом: подменённый вердикт REFUSED — и партия не начинается.

#### Позиции — не независимые наблюдения

Партия даёт восемьдесят позиций, делящих дебют, пешечную структуру и
исход. Считать их восемьюдесятью наблюдениями — это способ научить
модель запоминать партии и получить прекрасную кросс-валидацию.

Поэтому два правила, и они не пожелания, а код:

- из партии сохраняются **четыре** позиции, распределённые по её
  середине (дебют пропускается — он общий у всех и ничего не говорит об
  игроках; последние полуходы уже решены и размечают сами себя);
- **независимая единица — партия**. Всё статистическое — парные
  испытания, которых хотят ворота — считает партии, никогда не позиции.
  `Corpus.stats()` печатает оба числа рядом и подписывает, какое из них
  чему равно.

`MIN_ML_EXAMPLES = 1000` в `brain_factory` считает примеры. Набрать их
коррелированными позициями из тридцати партий значит выполнить число и
не выполнить его смысл.

#### Базовый игрок — это пол, а не решение

Подсчёт материала с мелким альфа-бета поиском стоит здесь, чтобы было с
кем играть и кого побеждать. Это контрольная рука: обучаемая оценка,
которая её не бьёт, ничего не заслужила. Называю прямо, чтобы не вышло,
будто рукописное решение протащено под видом старта.

Разделение, ради которого он так устроен: `choose_mechanism` отвечает
`algorithmic` для поиска (при данной оценке он вычислим точно) и
`classical_ml` для самой оценки. Поиск не учится, оценка учится.

#### Замерено на этой машине

| игрок | скорость | полуходов на партию |
|---|---|---|
| случайный | 65 000 партий/час | 285 |
| материал, глубина 1 | 85 000 партий/час | 118 |
| материал, глубина 2 | 3 000 партий/час | 130 |
| материал, глубина 3 | 275 партий/час | — |

Моя прежняя прикидка «сотни партий в сутки» была занижена примерно на
два порядка. Она была помечена как оценка, теперь есть замер.

Проверка вменяемости поиска: материал на глубине 2 против случайного,
20 партий — **19 побед, 1 ничья, 0 поражений (0.975)**. То есть поиск
действительно играет, а не производит легальный шум.

### Реестр находок — эксперимент не уходит в никуда

`mana/cognition/findings.py`. Смотреть — `MANA.exe --tried`.

**Пробел, названный пользователем словами:** «провал эксперимента мы тоже
не запишем, и этот тест уйдёт в никуда; если захочу вернуться, начну
сначала и потрачу время на повторение».

Это было в точности верно и оказалось тем же повторяющимся отказом
проекта на новом уровне: построен аппарат, измеряющий, помогает ли
изменение; измерение прошло; **его вывод не попал никуда, где машина
могла бы его прочитать**. От шахматного эксперимента остались корпус и
файл весов, а вывод — 0.4708 против материала на 240 партиях, 0.5 внутри
интервала — жил только в сообщении чата и в тексте коммита.

Ни одно из существующих хранилищ не подошло, и притянуть было бы хуже:

- `core/transaction.py` — восстановление после сбоя, отвечает «не
  осталось ли самоизменение недоделанным», а не «пробовали ли уже»;
- `cognition/exchange.py` — мутации генома между экземплярами, требует
  `mutation in MUTATIONS`. Шахматная оценка не мутация генома, а
  расширение словаря размыло бы границу, которая существует ради
  подписей и защиты от Sybil.

Поэтому это третье хранилище, сознательно, с узкой задачей.

**Отрицательный результат — самый ценный.** «Пробовали, не сработало»
экономит больше времени, чем «сработало»: второе обычно и так видно по
поведению, а первое невидимо по построению. `REJECTED` и `NOT_EVALUATED`
здесь полноправны — те же три состояния, что в `core/gates.py`.

**Время экономит не запись, а вопрос.** `already_tried()` спрашивается
**до** начала эксперимента, поэтому повтор опознаётся как повтор. Реестр,
которого никто не спрашивает, — это дневник, а вещей, построенных и ни к
чему не подключённых, в проекте и так хватало. Поэтому генератор
кандидатов теперь консультируется с реестром: уже отвергнутое при не
изменившихся условиях **опускается в конец списка, но остаётся видимым**
с пометкой. Скрывать было бы неверно.

**Находка — основание, а не запрет.** С каждой записью хранятся условия:
версия, размер и происхождение выборки, с чем сравнивали. Результат,
измеренный на тысяче партий на 2.34.0, говорит о тысяче партий на 2.34.0.
`stale_against()` показывает, что именно сдвинулось, и ничего не решает
за читателя:

```
тот же подход, те же условия     -> найдено, устарело: False
корпус 1000 -> 20000, глубина 2 -> 4:
    corpus_games: было 1000 стало 20000
    depth:        было 2    стало 4
```

Есть тест, который падает, если в модуле появится способ отказать в
запуске.

### Долги, найденные аудитом и пока не закрытые

- [ ] **Контекст доминирует над вопросом.** Ответ на «Привет, Мана» пересказывал погоду в Воронеже из прошлого хода — через двадцать минут и без наложения запросов. `[RECENT CONVERSATION]` кладёт прошлые ответы в промпт дословно, и маленькая модель на шести тысячах символов копирует самый ответоподобный текст перед собой. Тяжёлая форма (дословный повтор, похожесть 0.97) ловится `mana/echo_guard.py` и переспрашивается без вспомненной памяти. Лёгкая остаётся: ответ здоровается и следом пересказывает то же самое, и приходит это уже не из истории разговора, а из `[ACTIVE TASK]` и блоков свидетельств. Настоящее лечение — решить, какой контекст вообще должен видеть ответ.
- [ ] «Обученный роутер» учится только на бенчмарке, а его признаки — выходы тех же правил, которые он должен заменить.
  **С фазы 22 этот долг перестал быть спящим:** роутер включается по флагу HAS_SKLEARN, а до установки sklearn флаг был False и код молча не работал. Теперь он работает — со всеми своими известными пороками.
- [ ] UCB в `experience.py` без логарифма: разведка растёт как √total и забивает качество.
- [ ] Ключ кэша фитнеса не включает мозги, модели и факт патча кода.
- [ ] Политика песочницы — AST-денилист, обходимый через `f = eval`.
- [ ] Семантический поиск отсекает релевантное на этапе пре-фильтра.
- [ ] Полная переиндексация FTS при каждом старте.

## Что это НЕ решает

Пул мозгов расширяет то, **чем** MANA думает. Измерительный слой чинит
то, **по чему** оценивается её улучшение. Но:

- **Открытие пока не продемонстрировано.** Построен аппарат, который
  зафиксирует его, если оно случится, и честно скажет, если нет. Ни один
  закон ещё не достиг статуса `VALIDATED`.
- **Старый геном `PipelineSpec` всё ещё оценивается по 21 подстрочной
  задаче.** Новый измерительный слой существует, но эволюция пайплайна на
  него пока не переведена.
- **Бюджет вычислений — реальное ограничение.** Одна проверенная гипотеза
  по полной цепочке ≈ 3 600 вызовов; одно доказанное открытие — 5–20
  гипотез. При потолке бесплатных тарифов около 3 000 вызовов в сутки это
  недели прогона, а не часы.

## Разработка

```bash
python -m pytest -q          # 1131 passed, 8 skipped
python mana_run.py --version # продукт + версии всех подсистем
```

Версия продукта объявлена ровно в одном месте — `mana/version.py`. Каждая
подсистема версионируется отдельно, и версия поднимается **вместе с
изменением**, а не потом; `tests/test_versioning.py` падает, если
продуктовая версия изменилась без обновления теста.

Два теста, годами падавших на машине без `sklearn`, теперь проходят: не
потому, что их починили, а потому, что `sklearn` вошёл в список того, что
пакет обязан нести, и оказался установлен. На машине без него они снова
упадут — и это правильно, они меряют семантический поиск.

## Windows 10

MANA работает на Windows 10 (сборка 1607 и выше) так же, как на 11, с одним
отличием: **WebView2 Runtime**. В Windows 11 он встроен, в Windows 10 — нет, а
именно им рисуется окно.

Без него `webview.start()` падает внутри pywebview с «no suitable GUI
toolkit», а у windowed-сборки нет консоли, чтобы это сообщить. Пользователь
делает двойной щелчок и **не видит ничего** — худший вид отказа, потому что
искать нечего и заподозрить отсутствующий компонент, а не сломанную программу,
неоткуда.

Поэтому проверка идёт до импорта бэкенда и говорит, чего не хватает и что с
этим делать — в консоль и диалогом сразу, потому что эти два случая нужны
разным запускам. Установщик спрашивает то же самое **во время установки**, а не
при первом запуске: это момент, когда человек и так готов что-то поставить.

Отсутствие WebView2 не мешает установке — MANA работает и без окна,
`MANA.exe --cli`.

## Программы на этой машине

MANA умеет работать с установленными приложениями. Что доступно — видно на
вкладке «Программы» и в `--self-check`; чего нет, то говорит, чего именно
не хватает, а не отсутствует молча.

| возможность | чем обеспечена | что умеет |
|---|---|---|
| `docx` / `xlsx` | python-docx, openpyxl | чтение и запись Word- и Excel-файлов **без установленного Office** |
| `editor` | Notepad++ | открыть файл на нужной строке |
| `onec` | pywin32 + `V83.COMConnector` | запросы к 1С:Предприятие 8, запись с подтверждением |
| `onec_client` | `1cestart.exe`, `1cv8.exe` | запуск 1С и создание новых баз |

Office на машине разработки не установлен, и это оказалось удачным
ограничением: python-docx и openpyxl работают с самими файлами, поэтому
один и тот же код годится и там, где Office есть, и на сервере — и он
проверяем здесь, в отличие от COM-автоматизации отсутствующей программы.

Границу стоит знать: эти библиотеки правят файл, а не программу. Пересчёта
формул нет — `read_xlsx` возвращает либо текст формулы, либо значение,
сохранённое в файле той программой, которая открывала его последней, и
прямо сообщает, что именно вернул. Значение, закэшированное Excel в 2019
году, и значение, посчитанное сейчас, — разные факты.

### Запись в 1С

Запись — двухшаговый протокол, а не разрешение:

1. `onec_propose_write` описывает изменение и **читает текущие значения из
   базы**. Не пишет ничего.
2. Человек видит в окне «было → стало» по каждому реквизиту и подтверждает.
3. `onec_confirm_write` выполняет — и это единственный путь к записи.

Приватный исполнитель принимает объект заявки, который выдаёт только
`confirm`, поэтому «без подтверждения ничего не пишется» — свойство кода, а
не соглашение, о котором надо помнить. Заявка живёт 5 минут: она описывает
состояние базы, прочитанное тогда, и чем дольше лежит, тем менее это
описание верно. Перед записью текущие значения перечитываются, и если база
успела измениться — отказ вместо затирания чужой правки.

Флага «разрешить запись на сессию» здесь нет намеренно. Агент переписывает
собственный код, у его песочницы задокументированный обход, а в фазе 22.1
он умел ответить числом из чужой памяти на приветствие. Подтверждать нужно
операцию, а не намерение.

Учётные данные (`MANA_1C_CONNECT`, `MANA_1C_USER`, `MANA_1C_PASSWORD`)
живут в Windows Credential Manager через keyring — то же правило, что и
для ключей API: никогда в файлах, никогда в репозитории.

### Модель подбирается под машину

Свежая установка отказывает на всё, потому что языковой модели нет. Окно
говорит об этом — и тут же предлагает поставить, **подобрав размер под эту
машину**.

Подбор идёт от измерения, а не от таблицы. Декодирование упирается в полосу
памяти: каждый токен читает всю модель. Значит ожидаемая скорость — это полоса,
делённая на размер, и оба числа на конкретной машине известны: полоса
**измеряется**, размер берётся из каталога.

Обычный совет «8 ГБ памяти — бери 7B» игнорирует как раз тот множитель, который
решает, можно ли этим пользоваться. Две машины с одинаковой памятью и разной её
скоростью заслуживают разных ответов, а рекомендация, которая не может сказать
«около 11 токенов в секунду», — это рекомендация, которую невозможно оценить.

Умолчание — **не самая большая из влезающих**. На этой машине такое правило
выбирало 14B на 5.7 ток/с вместо 7B на 10.9: способнее и хуже, чтобы перед ней
сидеть. Поэтому по умолчанию берётся самая крупная из удобных, а более крупная
остаётся в списке для того, кому способность важнее задержки.

Видеокарта считается, только если ollama действительно может ей воспользоваться.
RX 580 держит 8 ГБ, до которых ollama не дотянется: ROCm выбросил gfx803. Учесть
их значило бы пообещать скорость, которой машина не даст, и не оставить человеку
способа понять почему.

Ничего не ставится само. `recommend()` и `status()` только смотрят; установка и
скачивание запускаются кнопкой. По окончании модель **подключается на горячую** —
пул опрашивает службу заново, перезапуск не нужен.

### Просьба выполняется, а не пересказывается

«Открой Notepad++» отвечало «Открываю Notepad++.» и **не вызывало ни одного
инструмента**. Десять инструментов слоя приложений были зарегистрированы и
недосягаемы: конвейер ответа вызывает жёстко прописанный список
(`llm_generate`, `web_search`, `verify_answer` и ещё несколько) и никогда не
обращается к реестру за инструментом, подходящим к просьбе. Модель
рассказывала о действии, действие не происходило.

Это худший отказ, какой проект может выдать. Всё остальное здесь построено
так, чтобы утверждение опиралось на измерение; ответ «открываю» там, где ничего
не открылось, не опирается ни на что.

`mana/apps/intent.py` распознаёт повелительное наклонение в начале сообщения и
вызывает инструмент. **Сопоставлением, а не моделью:** «Запусти 1С» не
двусмысленно, спрашивать об этом языковую модель значило бы добавить
зависимость, задержку и способ ошибиться. И это работает на установке, где
модели нет вообще, — то есть на свежей.

Распознаётся намеренно мало. «Как открыть Notepad++?» — вопрос о программе, а
не указание её запустить, и сопоставитель, срабатывающий на оба, начал бы
запускать программы тем, кто спрашивал совета.

Ответ строится **из исхода**, никогда из просьбы: отказ проходит насквозь как
отказ, потому что «не найден Notepad++» — полезный ответ, а «открываю» — ложный.

### Запуск 1С

Три вещи, которые просят в жизни, и все три — отдельные инструменты:

**«Запусти 1С»** → открывается окно выбора базы, базу выбираете вы. Никто
ничего не выбирает за вас: диалог 1С для этого и существует.

**«Запусти базу UT11-ER, логин такой-то»** → сразу в неё. Имя базы берётся
из вашего же списка; несуществующее — отказ с перечислением имеющихся.

**«Создай базу»** → инструмент **отказывает без пути**, и этот отказ и есть
вопрос «где разместить?». Вы отвечаете, база создаётся там, открывается
конфигуратор. Выбрать каталог за вас значило бы положить базу туда, где её
потом найдут случайно.

#### О пароле — прямо

1С принимает логин и пароль только через командную строку (`/N`, `/P`).
Windows позволяет **любой программе, запущенной от вашего имени, прочитать
командную строку чужого процесса без прав администратора** — это проверено
здесь, а не взято из документации: `Get-CimInstance Win32_Process` вернул
подставленный пароль дословно.

Значит, пока окно 1С открыто, переданный так пароль виден другим программам.
Способа передать его в GUI-клиент иначе нет. Поэтому: передавать можно, но
каждый запуск с паролем возвращает `warning` об этом, в возвращаемых данных
и в трассировке пароля нет, а если пароль не передавать — 1С спросит его
сама, своим окном. Умолчать об этом было бы проще и неправильно.

#### Два дефекта, найденных проверкой на настоящей 1С

`subprocess` строит командную строку из списка аргументов сам и экранирует
кавычки внутри `File="C:\путь";` как `\"`, отчего 1С отвечает «Неверные или
отсутствующие параметры соединения». Передача аргумента без кавычек работает
— ровно до первого пути с пробелом, а все базы здесь лежат в `C:\1С\Базы\…`.
Командная строка собирается вручную.

`1cestart.exe` — это шим: он определяет версию, запускает `1cv8s.exe` и
завершается меньше чем за секунду. Первая версия возвращала pid шима, уже
мёртвый к моменту проверки, — тот, кто спросил бы «запустилось ли», получил
бы «нет» при открытом на экране окне. Теперь окно ищется среди процессов, а
если не нашлось, так и сказано.

## Скрытая выборка теперь у каждого экземпляра своя

`HOLDOUT_V0` и `HOLDOUT_V1` задавались фиксированным зерном — значит **каждая
копия MANA порождала одни и те же скрытые задачи**. Пока копия одна, это
безвредно. Как только два экземпляра начинают чем-то обмениваться, это канал
утечки по построению: достаточно одному опубликовать что-нибудь, подогнанное
под скрытую выборку, и приёмочные ворота становятся недействительны **у всех
сразу**, причём молча — в самой оценке ничего не говорит, на какой выборке она
получена.

Зерно V1 солится идентификатором установки: случайным, сгенерированным один
раз и лежащим рядом с состоянием агента. Утечка перестаёт быть заразной, а
совпадение вердиктов у двух экземпляров перестаёт быть следствием того, что
они тянули одни и те же задачи, — то есть становится воспроизведением.

**V0 не солится, и это намеренно.** Каждая скрытая оценка, записанная до фазы
18, снята ровно на этих задачах; перерисовать их поштучно для каждой установки
значило бы задним числом изменить смысл всех тех чисел. Быть замороженным —
единственное, ради чего V0 существует.

`Holdout.identity` возвращает `v0` для несолёного и `v1+<отпечаток>` для
солёного, и это значение попадает в каждый `HiddenResult`. Поэтому сравнение
оценок между экземплярами не совпадёт по строке вместо того, чтобы тихо
сравнить числа, снятые на разных задачах.

Отпечаток — восьмисимвольный дайджест: его хватает, чтобы отличить экземпляры
и посчитать, на скольких результат воспроизвёлся, и не хватает, чтобы сказать
что-либо о том, чья это машина. Имя хоста или MAC не годились бы: они уехали
бы вместе с каждой общей записью.

## Мост между установками

Через мост едут **гипотезы, а не вердикты**.

Приёмочный аппарат MANA чего-то стоит потому, что каждое принятое утверждение
измерено **здесь**: парный эксперимент, McNemar, минимальный запас, своя
скрытая выборка. Импорт чужого вердикта всё это выбрасывает — у того
экземпляра другие мозги, другое железо, другое распределение задач и, с фазы
25, другая скрытая выборка. «Принято там» здесь не доказательство, а общее
хранилище вердиктов превращает систему доказательств в систему слухов.

Поэтому мост несёт **что попробовать**. Едет мутация с параметрами, а не
готовый геном: получатель строит кандидата от **своего** родителя и судит
своими воротами.

```bash
python scripts/run_exchange.py export обмен.json
python scripts/run_exchange.py import обмен-от-коллеги.json
python scripts/run_exchange.py            # где что воспроизвелось

# то же самое из установленного приложения, без клона репозитория:
MANA.exe --exchange export обмен.json
MANA.exe --exchange import обмен-от-коллеги.json
MANA.exe --exchange show
python scripts/rehearse_exchange.py         # репетиция обмена на одной машине
```

Три следствия, и ни одно не очевидно:

**Отравление решается само.** Если едут только гипотезы, испорченный или
враждебный экземпляр ничего сломать не может — плохая гипотеза не проходит
локальные ворота. Доверие не требуется вообще; подписи нужны против спама, а
не ради корректности.

**Делится дорогая половина.** Исследовательский цикл тратит основной бюджет
на решение, *что* мерить; само измерение сравнительно дёшево. Мост умножает
затратную часть и оставляет ценную локальной.

**Появляется внешняя валидность.** Один экземпляр знает только «здесь верно».
Двенадцать могут знать «принято в девяти, а три исключения объединяет
отсутствие локальной модели» — это уже находка, а не результат. Отрицательные
результаты здесь важнее всего: REJECTED и NOT_EVALUATED у MANA полноправные
вердикты, а хранилище «пробовали, не вышло» — именно то, что человеческая
наука систематически теряет.

Гипотезы попадают в очередь сами: `ResearchCycle` записывает своё
предложение **до подтверждающего эксперимента** и свой вердикт после. Записать
только подтверждённое значило бы делиться ровно тем, что каждый и так выведет;
ценность гипотезы в том, что у кого-то может найтись свидетельство, которого
здесь не хватило.

```bash
python scripts/run_research_cycle.py --budget 300 --exchange очередь.json
```

Параметры делятся на **поведенческие и пояснительные**. `description`
шаблона — текст для человека, он не влияет на то, что шаблон делает, и его
отбрасывают. `steps` отбросить нельзя: получилась бы гипотеза, означающая не
то, что предлагали, и чужой экземпляр померил бы не то, о чём никто не
догадался бы. Разделение задано явным списком, а не догадкой по типу значения.

Непередаваемая гипотеза не теряется: она остаётся в очереди с пометкой и
причиной, потому что попробовать её локально по-прежнему стоит. Выгрузка
фильтрует, так что уехать она не может.

### Личность установки — пара ключей

Идентичность экземпляра — это ключевая пара Ed25519. Ни регистрации, ни
сервера, ни центра доверия: личность **и есть** ключ. Это единственное, что
стоит взять у того, как устроены криптовалютные сети.

Подпись закрывает **выдачу себя за другого**. До неё `Report.instance` был
самозаявленной строкой: один экземпляр мог выписать двенадцать отпечатков и
изготовить «подтверждено на двенадцати установках» — атака Сивиллы на счётчик
воспроизведений, единственная настоящая дыра федерации. Теперь отчёт несёт
подпись над собственным содержимым и публичный ключ, а отпечаток проверяется
как принадлежащий этому ключу. Обе половины обязательны: проверять только
подпись значило бы позволить подписаться своим ключом, назвавшись чужим
отпечатком.

Чего подпись **не** даёт — устойчивости к Сивилле: сгенерировать двенадцать
пар никто не мешает. Криптовалюты отвечают на это доказательством работы, и
оно дорого именно потому, что им нужно согласие между сторонами, которые не
могут проверить утверждение сами. MANA проверяет сама — локальными воротами на
локальной скрытой выборке, — поэтому согласие ей не нужно вовсе, а дорогая
машинерия покупала бы ничто. Сивиллу здесь ограничивает решение о том, чьи
ключи учитывать, — как в `known_hosts`, доверием по знакомству.

Блокчейн был бы не просто лишним, а **враждебным** архитектуре: это машина по
производству глобального согласия, а вся ценность MANA в отказе принимать
чужой вердикт как истину.

**Зерно скрытой выборки выводится из ЗАКРЫТОГО ключа, не из открытого.** Эта
ловушка чуть не сработала: соль существует, чтобы чужая установка не могла
подогнать что-либо под здешнюю скрытую выборку, а вывод из публичного ключа —
который едет в каждом пакете — позволил бы кому угодно восстановить эту
выборку и обнулить фазу 25 целиком.

Что разрешено внутри гипотезы: имя мутации и параметры, где строки обязаны
выглядеть идентификаторами — буквы, цифры, `_`, `.`, `-`, без пробелов и без
кириллицы. Это разрешительный список по форме: имя оператора проходит,
`Номенклатура` и набранный человеком текст задачи — нет. Поле `rationale`
не выгружается вовсе: оно порождается локально из локальных наблюдений и
цитирует их с наибольшей вероятностью.

Идентификатор гипотезы выводится из содержимого, а не назначается. Два
экземпляра, независимо додумавшиеся до одного и того же, получают один
идентификатор — иначе каждое переоткрытие выглядело бы новой идеей и
воспроизведения было бы не посчитать. Он же ловит правку в пути.

Воспроизведения считаются по **средам, а не по отчётам**: экземпляр,
прогнавший опыт десять раз, имеет десять свидетельств и по-прежнему одну
среду. И NOT_EVALUATED не считается несогласием — «не хватило наблюдений,
чтобы судить» и «не работает» это разные факты.

## Связь между экземплярами

Два экземпляра обмениваются пакетами по сети, без переноса файлов руками.

```bash
MANA.exe --peer show                      # свой ключ, адреса, известные узлы
MANA.exe --peer serve                     # слушать (по умолчанию 0.0.0.0:8787)
MANA.exe --peer hello 192.168.0.5:8787    # кто там отвечает
MANA.exe --peer add <ключ> <адрес> <имя>  # признать узел
MANA.exe --peer sync 192.168.0.5:8787     # обменяться
```

### Почему это отдельная точка входа

`mana_desktop.server` **никогда** не выставляется в сеть. Он отвечает на
`/api/ask` — исполнение кода в песочнице, `/api/onec/confirm` — запись в боевую
торговую базу, `/api/key` — хранение ключей API. На открытом порту это удалённое
исполнение кода с доступом к чужим учётным записям, и никакая аутентификация
перед ним не сделает его разумным для публикации.

Поэтому у связи своя точка входа с **тремя маршрутами и без четвёртого**:
`GET /peer/hello`, `GET /peer/bundle`, `POST /peer/bundle`. Ни сессии, ни
агента, ни песочницы, ни пути к ним. Поверхность, которую можно прочесть за
один присест, — то самое свойство, ради которого это не ещё один обработчик в
существующем сервере.

### Спаривание взаимно

Каждый запрос подписан, и подпись покрывает метод, путь, отпечаток тела и метку
времени: перехваченный запрос нельзя повторить ни на другом маршруте, ни с
другим телом, и он перестаёт работать, состарившись.

Но подписывать свои запросы значит доказать себя **им**, и ничего не сказать о
них **нам**. Прогон это поймал: синхронизация проходила с узлом, которого
вызывающий не добавлял. Без проверки подставной узел по тому же адресу принял бы
наш пакет и вернул свой — с отчётами, подписанными свежей парой ключей, которые
проверяются как подписанные, приходят от никем не добавленного экземпляра и
считаются ещё одной средой. Это снова атака Сивиллы, теперь по сети. Рискуют не
данные — в пакетах их нет по построению, — а счёт, единственное, что федерация и
производит.

Поэтому `sync` сперва спрашивает `hello` и отказывается говорить с ключом,
которого нет в списке. Список — по образцу `known_hosts`: подпись доказывает,
**кто** прислал, а список решает, **кого** слушать.

Отказы намеренно скучные: «не опознан» на всё — неизвестный ключ, неверная
подпись, устаревшая метка. Ошибка, объясняющая, какая из трёх проверок не
прошла, — это оракул для подбора двух остальных.

### Чего нет намеренно

**Шифрования.** Пакеты не несут приватного по построению, поэтому этому трафику
нужны подлинность и целостность, а подпись даёт обе. Утверждение верно для
пакетов обмена и перестаёт быть верным, как только по этому каналу поедет что-то
приватное.

**Обнаружения в сети.** Адрес надо записать. Автопоиск означает широковещание,
то есть поверхность без соразмерной пользы, когда весь список узлов — две
машины одного человека.
