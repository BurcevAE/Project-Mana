# Глубина рассуждения. D0: единица и лестница

**Статус:** спецификация принята владельцем 2026-09-15 (решения — раздел 7). Кода и
прогонов пока нет. Документ решает, что считать единицей рассуждения и чем мерить
глубину, прежде чем строить механизм.

---

## 0. Гипотеза и порядок

> **H3.** MANA способна создавать новые проверяемые подзадачи из промежуточных
> результатов собственного рассуждения и рекурсивно использовать их решения как
> новые шаги.
>
> **H3a** — создание подзадач: из какого результата какой вопрос задать.
> **H3b** — выбор: какую из возможных подзадач исследовать.

Отличие от нынешнего поиска: поиск discovery порождает *состояния* в одном и том же
пространстве программ (правка за правкой). Рассуждение порождает *задачи*, которых не
существовало до предыдущего результата: вопрос Q2(X) появляется только после ответа X.

Порядок проверяет сначала наличие способности, затем её автономность, и только потом
встраивает её в общую архитектуру:

| Шаг | Вопрос | Кто строит |
|---|---|---|
| **D0** | спецификация: единица, лестница, контроли, правила проверки; затем прибор — лестница и её калибровка | — |
| **D1** | есть ли вообще выигрыш от рекурсивных подцелей? Сначала интерпретатор задач (с пустым каталогом — ровно плоский поиск), затем каталог руками против плоского поиска | мы; судит ядро |
| **D2** | может ли MANA сама выбирать и строить подцели из каталога: из какого результата спрашивать, какую подзадачу исследовать (H3b; линия P2d — опыт о ценности исследования) | MANA |
| **D3** | может ли MANA придумать новый тип разложения: операторы вопросов из операций вычислителя, включая «новый элемент» (H3a в полном смысле — это Н3) | MANA |
| **D4** | перенос: шум (обязательная вторая волна), новые миры, новые домены | — |

После D2 решается, становится ли механизм частью `research` (раздел 2.4).

## 1. Что уже есть — и почему это не шестой язык

У MANA уже есть вопрос как объект, но не рекурсия вопросов.

| Где | Что там есть | Чего нет |
|---|---|---|
| `research/contract.py`, `research/loop.py`, `core/standing.py` | `Question` (о чём, почему открыт, конкурирующие объяснения), `Stakes`, пробы по битам на стоимость, закрытие по экономике, статус ответа в неизменяемом ядре | вопрос задан извне; цикл плоский; ответ не становится новым вопросом |
| замороженный корпус методов (M1b, M1c, M1e) | PROBE — меньшая версия задачи ради информации; выбор проб по ценности информации; разбиение данных по скрытой неоднородности | содержание пробы не зависит от прошлого ответа; нет сборки ответов |
| `discovery` | поиск как объект (R1), генератор изменений (R2), ворота ядра, миры с записанной истиной, MDL | задачи внутри задачи |

**Решение.** Единица определяется абстрактно, а реализуется сначала в discovery: там
проверка точная и дешёвая, истина записана в мире, а поиск уже является объектом.
`research` в серии D не трогается до конца D2. Решение «не объединять языки» остаётся в
силе.

## 2. Единица рассуждения

### 2.1 Задача

```text
Problem
  inputs     столбцы: переменные мира и производные — результаты решённых подзадач
  target     цель на каждой точке
  domain     точки, где цель задана; вне их — «неважно»
  verdict    кратчайшее описание на domain (биты программы + биты ошибок на domain)
  budget     вычисления; все подзадачи тратят один общий бюджет
  origin     родитель, оператор, который её создал, и результаты, из которых вычислена
             её спецификация (граф зависимостей, раздел 3)
```

Реализационное замечание: domain — это просто сужение данных. Точки вне domain не
входят в данные подзадачи, так что плоский поиск и MDL остаются как есть.

Ответ на задачу — программа над `inputs` с её битами на `domain`. Решила ли она задачу,
определяет не подзадача, а родитель: его собственный вердикт после сборки (2.2).

### 2.2 Шаг рассуждения

```text
q : (P, R)  → P'        оператор вопроса: новая задача из задачи и промежуточного результата
решить P'   → R'        тем же механизмом, рекурсивно
c : (R, R') → R''       оператор сборки: кандидат для P, проверяется вердиктом P
```

Требования к операторам:

- **Из семантики языка, без знания о мире.** Операторы строятся из того, что делает
  вычислитель: вычислить программу, вычесть, сравнить, сузить множество точек, добавить
  столбец.
- **Корректность сборки.** Если R' точно решает P' на её domain, то c(R, R') точно
  решает P на его domain, по построению. Вердикт родителя всё равно применяется.
- **Каталог объявляется заранее** и фиксирован на каждом шаге серии D.

### 2.3 Каталог D1 (руками, как диагностика — так же, как «взгляд» в P1)

| Оператор | Вопрос P' | Сборка | Что обращает |
|---|---|---|---|
| `остаток(A)` | цель' = цель − A, domain тот же | `A + R'` | сложение |
| `остаток-(A)` | цель' = A − цель | `A − R'` | вычитание |
| `случаи(A, B)` | булева цель: 1 где цель = A ≠ B, 0 где цель = B ≠ A; «неважно», где A = B; допустимо, только если нет точек, где цель ≠ A и цель ≠ B | `if(R', A, B)` | ветвление |
| `промахи(R)` | domain' = точки, где R ошибается; цель та же | вместе со `случаями`: `if(C, R', R)` | сужение |

Откуда берутся A, B, R — частичные программы, на которых строится вопрос, — в D1
задаётся фиксированным и объявленным правилом. Научиться выбирать их — это D2.

**`новый элемент(R)`** — inputs' = inputs ∪ {u = R}, сборка подставляет R вместо u, то
есть решённое становится листом. **В каталог D1 и D2 не входит, решено владельцем.** Это
самый «рассуждающий» оператор. Если написать его руками, D3 потеряет смысл. Он
появляется только как одна из возможностей метаязыка D3.

### 2.4 Соответствие с контрактом исследования — решается после D2

| Контракт | Задача D |
|---|---|
| `Question.subject` | «программа для target на domain над inputs» |
| `Question.why_open` | «плоский поиск не нашёл описания короче таблицы» или «оператор q родителя» |
| `Question.explanations` | кандидаты-программы |
| `Stakes.error_cost`, `weight` | цена неверной сборки для родителя; вес точек domain |
| `core/standing` | статус ответа подзадачи: проверено на domain / условно |

**Критерий решения после D2.** Если существующий `research.Question` выражает цепочку
«вопрос → подвопрос → ответ → сборка родителя» без семантических костылей, механизм
переносится в `research`. Если нет, это записывается как архитектурный результат:
нынешний `Question` — объект исследования, но не объект рассуждения.

## 3. Что считается глубиной

Четыре величины. Смешивать их нельзя.

**Использованная глубина** — вложенность шагов в трассе решения. Её сообщают, но никогда
не утверждают: систему легко обмануть, наплодив подзадачи.

**Эффективная глубина решения** — каждый уровень должен давать новую вычислимую
информацию, необходимую родителю. По трассе решения:

1. **Зависимость.** У каждой подзадачи записано, из каких результатов вычислена её
   спецификация (цель, domain, входы). Ребро Pᵢ → Pⱼ означает, что спецификация Pⱼ
   вычислена из результата Rᵢ.
2. **Нетривиальность.** P' отличается от P хотя бы целью, domain или входами. И ни R',
   ни R по отдельности не решают P: сборка не вырождается в один из своих аргументов.
   Цепочка «P → P1 = P → P2 = P» отсекается здесь.
3. **Необходимость (сворачивание).** Для каждой внутренней вершины запускается плоский
   поиск на её задаче с тем бюджетом, который съело её поддерево. Если он решает,
   уровень не нужен и сворачивается.

Эффективная глубина — длина самой длинной цепочки в графе зависимостей после
сворачивания ненужных уровней:

```text
глубина 1   решается напрямую
глубина 2   нужен результат P1
глубина 3   нужен результат P2, который зависит от P1
...
```

**Необходимая глубина ступени** — свойство экземпляра задачи при бюджете B, относительно
плоского поиска и каталога. Экземпляр имеет необходимую глубину k, если:

1. плоский поиск (поиск как есть, с пределом размера, достаточным для записи истины, и с
   тем же B) его не решает;
2. существует дерево разложения эффективной глубины k из объявленного каталога, каждая
   вершина которого решается плоским поиском в пределах своей доли B;
3. дерева меньшей эффективной глубины, удовлетворяющего пункту 2, нет.

Проверяется калибровкой (4.3).

**Достигнутая глубина системы** — наибольшая ступень, на которой система решает не
меньше θ свежих экземпляров при бюджете B, со всеми вычислениями в счёте. Для каждого
решённого экземпляра сообщается эффективная глубина решения. Если она оказалась меньше
необходимой глубины ступени, это находка против лестницы — ступень была не так глубока, —
а не успех.

### 3.1 Найдена и эффективна

- **Глубина найдена** — свойство прибора и D1: есть задача, которую плоский поиск не
  решает при B, а рекурсивная конструкция глубины k решает при том же B.
- **Глубина эффективна** — свойство утверждений о MANA (D1–D3): выигрыш при одном бюджете,
  в который входят все четыре статьи цены, и эффективная глубина решений не меньше
  заявленной.

**Счёт цены** — четыре статьи в одном бюджете B, сообщаются раздельно:

| Статья | Что считается |
|---|---|
| поиск | вычисления программ внутри подзадач |
| построение подзадач | вычисления A, B, R на данных, остатки, маски, сужения |
| сборка | вычисления кандидатов c(R, R') |
| проверка | вердикты родителей и сворачивание при подсчёте эффективной глубины |

Сворачивание — инструмент измерения, а не часть решения. Его стоимость сообщается
отдельно и в бюджет системы не входит, иначе измерение меняло бы то, что меряет.

## 4. Лестница — измерительный прибор

### 4.1 Принципы

- **Семейства проектируются до механизма.** Истина записана в мире; обучающиеся модули её
  не импортируют — как сейчас, тест читает их исходники.
- **Экземпляры порождаются, а не выбираются.** Ступень k — генератор истин: k уровней
  разложения над малыми атомами (размер ≤ 5). Атомы выбираются случайно по сиду из
  объявленного распределения.
- **Семейства:**
  - **R, остатки** — суммы атомов;
  - **S, случаи** — вложенные ветвления;
  - **M, смешанное** — R и S чередуются; глубина считает все уровни;
  - **F, новый элемент** — условия и суммы над промежуточными величинами (как T4, но не
    T4): чтобы спросить второй вопрос, нужен ответ на первый. Промежуточная величина
    входит в истину **больше одного раза**. Если она входит один раз, каталог D1 решает
    условие как отдельную подзадачу, и «новый элемент» не нужен. Недоступность F для
    каталога D1–D2 не предполагается, а проверяется калибровкой (4.3). Это целевое
    семейство D3; строится отдельным шагом после R, S, M.
- **Только достижимое плоским поиском.** Истины собираются из того, до чего плоский поиск
  доходит своими правками: листья, `+`, `−`, `if`; сравнение — только как условие `if`.
  Иначе плоский поиск проигрывал бы недостижимости, а не глубине. По той же причине атомы
  R — ветвления, а не линейные суммы: сумма линейных атомов сворачивается в одну короткую
  линейную форму, и глубины у неё нет.
- **Опознаваемость.** Каждый уровень восстановим из своей подзадачи (например, в S каждая
  ветвь покрывает не меньше 20% точек). Проверяется оракульным разложением (4.3).
- **Честность представления.** Предел размера плоского поиска на каждой ступени не
  меньше размера истины плюс 2. Плоский поиск должен проигрывать бюджету, а не пределу
  размера.
- **Как в существующих мирах:** 3–4 переменные, значения 0..9, 200 обучающих точек,
  оценка по всем состояниям мира.
- **Размер:** R, S, M, F по 5 ступеней; 10 сидов на ступень для калибровки; для каждого
  утверждения — отдельные свежие сиды.

### 4.2 Контроли

| Контроль | Что это | Что должно быть | В первых воротах |
|---|---|---|---|
| **C0, плоские** | задачи глубины 1: новые экземпляры в духе W0 | разложение не проигрывает плоскому поиску (иначе это контрпримеры) | да |
| **C1, вне каталога** | истины того же размера, чья структура каталогу недоступна (например, сравнение внутри арифметики) | выигрыша нет; выигрыш значит, что мера протекает | да |
| **S, случаи** (контроль с первой калибровки) | разложение, родное для плоского поиска: его правка «добавить условие» — жадный разбор по случаям, S3 он решил 10 из 10 (4.6) | D1 не выигрывает и не проигрывает; проигрыш — контрпример | да |
| **C2, шум** | семейства с 10% случайных исходов | разложение не покупает шум глубиной | **нет** — объявлен здесь, обязательная вторая волна (D4) |
| **T4, W4** | вне лестницы и вне любого обучения серии D | — | только перенос |

Шум не входит в первую калибровку и первые ворота, чтобы отрицательный результат не
смешал две причины: не работает рекурсивное разложение или не работает работа с шумной
информацией. C2 объявлен уже в D0, поэтому не может стать удобным исключением потом.

### 4.3 Калибровка прибора (после реализации лестницы, до D1)

Только детерминированные миры. Прогноз объявляется до прогона:

- плоский поиск решает ступени до k₀ (ожидание: k₀ = 1–2) и не решает выше при бюджете B;
- **оракульное разложение** решает все ступени R, S, M: на каждом уровне подзадача
  задаётся истинным промежуточным результатом, а решается плоским поиском в пределах
  своей доли B. Для F — два оракула. Оракул с `новым элементом` должен решать: F
  опознаваемо. Оракул только с каталогом D1 должен не решать: иначе F не годится как
  целевое семейство D3. Ступень, которую оракул не решает, не опознаваема и из лестницы
  убирается;
- плоский поиск решает C0; на C1 оракульного выигрыша нет по построению.

Лестница считается прибором, только если калибровка показала разрыв «плоский — оракул»,
начиная с какой-то ступени. Нет разрыва — нечего мерить.

### 4.4 Калибровка R, S, M: прогноз до прогона (2026-09-15, `scripts/run_ladder_calibration.py`)

Сиды 0..9, бюджет 400k, только детерминированные миры. Предел размера плоского поиска —
размер истины плюс 2. Оракул делит тот же бюджет поровну между кусками, которые он
оставляет плоскому поиску.

- **Плоский поиск:**
  - ступень 1 (C0) решает 10 из 10 во всех семействах — это одно `if(c, a, b)`, как W0;
  - ступень 2: S2 и M2 (вложенный случай, размер 11) — 3–7 из 10; R2 (сумма двух
    условий, размер 13) — 0–3 из 10;
  - ступени 3–5: 0–1 из 10 в каждом семействе.

  Значит, k₀ = 1 для R и 1–2 для S и M.
- **Оракул:**
  - R — 10 из 10 на каждой ступени, но это мало что показывает (ищется только последний
    атом);
  - S и M — не меньше 8 из 10 на каждой ступени. Отказы, если будут, — там, где
    найденный на промахах остаток расходится с истиной вне своих точек и ни одна ветвь
    не права;
  - медиана вычислений у S и M — заметно меньше 400k.
- **C1:** плоский поиск решает 0–3 из 10.

Если так, лестница — прибор: плоский поиск падает на ступени 2–3, а оракул держится до
ступени 5 в S и M. Если плоский поиск решает ступени 3 и выше часто, лестница мелкая и её
надо поднять. Если оракул не решает ступень, она не опознаваема и убирается.

### 4.5 Находка до калибровки: вердикт не отличает двузначную цель от её дополнения

Проверка оракула на сиде 99 (вне сидов калибровки, при полном бюджете) не решила ни
одного экземпляра. Каждый раз кусок был неверен на всех своих точках (200 из 200, 85 из
85…). На R2/99 остаток — `if((6 < w), 1, 0)`, а плоский поиск вернул
`if((6 < w), 0, 1)`:

| программа | неверно | биты программы | биты ошибок | всего |
|---|---|---|---|---|
| `if((6 < w), 1, 0)` | 0 | 29.51 | 7.65 | 37.16 |
| `if((6 < w), 0, 1)` | 200 | 29.51 | 7.65 | 37.16 |
| `if((w < 7), 0, 1)` | 0 | 29.51 | 7.65 | 37.16 |

На двух значениях неверная догадка внутри алфавита бесплатно называет верное, а выбрать
все n неверных точек можно одним способом: «всегда неверно» описывается так же коротко,
как «всегда верно». Ничью вердикт решает текстом программы, а цифры сортируются раньше
букв и 0 раньше 1. Поэтому дополнение выигрывает систематически, а не в половине случаев.

Каждый уровень случаев порождает двузначную подзадачу — условие. Каталог D1 ломался бы
на этом по причине, не связанной с глубиной. Калибровка до правки не запускалась.

**Исправлено (решение владельца, 2026-09-15).** Мера описания не менялась. Изменился
только порядок при точной ничьей: при равных битах и размере ответом становится
программа, неверная на меньшем числе точек, и только потом решает текст. Изменения в
`search.py` 1.9 и `policy.run` 1.6 одинаковые:
- ответ — кратчайшее из оценённого по ключу «биты, размер, неверные точки, текст»;
- в конце прогона ответ заменяется только программой с теми же битами и размером, но
  меньшим числом неверных точек;
- порядок луча, счёт строгих улучшений и терпение — как были.

Проверено:
- два теста: верная программа, а не дополнение; равно верные программы различаются
  только текстом, без особого случая;
- эквивалентность R1;
- 70 прогонов (семь вопросов × сиды 0..9) до и после правки совпали во всех полях:
  ответ, биты, вычисления, раунды, где найден, кривая anytime.

**Наблюдение, не исправлено — свойство самой меры.** После правки оракул на сиде 99
решает R2, M3 и S5, но не S3. Его кусок-условие оказался составным: остаток найден
только на промахах ветви. Плоский поиск за свою долю бюджета точного составного условия
не нашёл и вернул `if((z < y), w, 0)` — неверную на всех 85 точках, но короткую по
описанию. На двух значениях неверная догадка внутри алфавита ничего не стоит, вне
алфавита стоит бит. Поэтому программа, идущая против цели, бывает кратчайшим описанием
и без всякой ничьей. Это мера, а не порядок при ничьей; по решению владельца мера не
меняется. Калибровка отмечает такие куски отдельно («двузначная цель, ответ против
цели»), чтобы они не смешивались с кусками, которые просто не найдены.

## 6. Риски, названные заранее

1. **D1b почти наверняка «сработает» на R и S:** обращения сложения и ветвления
   очевидны. Настоящие вопросы — D2 (автономность) и D3 (новый тип разложения).
2. **Опознаваемость в R.** Жадный остаток работает, только если хотя бы один атом —
   кратчайшее описание своей подзадачи. Это свойство лестницы, его измеряет калибровка, а
   не чинят потом.
3. **Экспонента переедет в пространство вопросов.** Возможных пар (A, B) и остатков
   много. Фиксированное правило D1 может оказаться дороже плоского поиска — это тоже
   результат, и он же мотивирует D2.
4. **Относительность.** «Необходимая глубина» определена относительно плоского поиска
   и каталога. Поиск как есть замораживается на всю серию D.
