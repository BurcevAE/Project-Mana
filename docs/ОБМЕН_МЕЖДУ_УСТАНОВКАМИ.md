# Проверка обмена на второй машине

Порядок действий, чтобы две установки MANA обменялись опытом и стало видно,
где их выводы расходятся. Расхождение — это и есть цель: оно означает, что
изменение **условно**, а условие — факт про среды, которого ни один экземпляр
в одиночку увидеть не может.

## Сначала репетиция, не вставая с места

```bash
python scripts/rehearse_exchange.py
```

Поднимает оба экземпляра в отдельных процессах, с отдельными каталогами
состояния и отдельными идентификаторами — то есть **со своими скрытыми
выборками**, как на разных машинах. Прогоняет полную цепочку и показывает, как
выглядит найденное расхождение.

Занимает секунды. Если протокол где-то дырявый, выяснить это лучше здесь, чем
после того, как вы полдня разворачивали вторую машину.

Единственное, чего репетиция не даёт, — настоящих экспериментов: вердикты в
ней задаются сценарием. На второй машине их выносят ворота, и это вся разница.

## Что нужно на второй машине

| | |
|---|---|
| MANA | установщик из `dist/`, либо клон репозитория |
| Мозги | хотя бы один рабочий: ollama локально или ключ внешнего провайдера |
| Идентификатор | **ничего не делать** — создастся сам при первом запуске |

Проверить, что установка живая и знает, чем располагает:

```bash
MANA.exe --self-check
```

Ждать 7 проверок из 7. Если меньше — обмен не имеет смысла: экземпляр, который
не может ничего измерить, вернёт одни `NOT_EVALUATED`.

### Убедиться, что выборки действительно разные

Это единственное, что стоит проверить руками до всего остального. На **каждой**
машине:

```bash
python -c "from mana.core import splits, identity; print(identity.fingerprint(), splits.HOLDOUT_V1.identity, splits.HOLDOUT_V1.effective_seed())"
```

Отпечатки и зёрна обязаны отличаться. Если совпали — где-то выставлена
переменная `MANA_INSTANCE_ID` в одно и то же значение, и тогда согласие
экземпляров ничего не значит: они тянут одни и те же скрытые задачи.

## Сам обмен

**1. На машине А** — накопить гипотезы настоящим циклом:

```bash
python scripts/run_research_cycle.py --budget 300 --steps 6 --exchange очередь.json
python scripts/run_exchange.py --export пакет-от-А.json
```

**2. Перенести** `пакет-от-А.json` на машину Б. Чем угодно: флешкой, почтой,
git. Файл не содержит ни текстов задач, ни запросов, ни имён из конфигураций —
только структурные идентификаторы, вердикты и отпечатки. Его можно открыть
блокнотом и убедиться в этом самому.

**3. На машине Б** — принять и проверить **своими** воротами:

```bash
python scripts/run_exchange.py --import пакет-от-А.json
python scripts/run_research_cycle.py --budget 300 --steps 6 --exchange очередь.json
python scripts/run_exchange.py --export пакет-от-Б.json
```

Импорт кладёт чужие гипотезы в очередь и **не принимает ни одного чужого
вердикта как истину**. Скрипт скажет это прямо при импорте.

**4. Обратно на машине А**:

```bash
python scripts/run_exchange.py --import пакет-от-Б.json
python scripts/run_exchange.py --show
```

## Что читать в выводе

```
что из этого следует:
  РАСХОЖДЕНИЯ      1  принято на одних, отклонено на других — изменение условно
  подтверждено     0  судили не меньше 3, все приняли
  опровергнуто     0  все отклонили — результат, который обычно теряют
  не решено        2  рулений слишком мало, чтобы говорить о чём-то
```

**Расхождения — главное.** Одна гипотеза, два разных вердикта. Дальше стоит
искать, чем среды отличаются: составом мозгов, железом, распределением задач.
Ответ на это — уже находка, а не результат.

**«Не решено» на двух машинах будет почти всё**, и это нормально: для согласия
нужно не меньше трёх судивших экземпляров. Два — не закономерность, а два.
Расхождение при этом видно уже с двух, потому что одного противоречия
достаточно, чтобы понять: утверждение условное.

**«Опровергнуто» стоит ровно столько же, сколько «подтверждено».** Хранилище
«пробовали, не вышло» — это то, что человеческая наука систематически теряет,
потому что неудачные опыты не публикуют.

## Чего ждать честно

С двух машин вы не получите ни подтверждений, ни опровержений — только
расхождения и «не решено». Польза первого прогона в другом: убедиться, что
цепочка замкнута, что в файле нет ничего лишнего и что вердикты действительно
выносятся заново, а не переносятся.

Смысл начинается с третьей установки. С двенадцати появляется то, ради чего всё
строилось: «принято в девяти, а три исключения объединяет отсутствие локальной
модели».
